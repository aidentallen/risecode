# risecode 0.11.3 — Responses protocol

[All versions](README.md) · [Changelog](../../CHANGELOG.md) · [Project home](../../README.md)

Historical release: the Agent feature and its guides were removed in [0.13.1](v0.13.1.md).

AI Settings now selects Chat Completions or Responses explicitly. Existing saved
connections keep Chat Completions. Hosted and loopback endpoints use the selected
route; changing protocols does not trigger automatic provider fallback.

The Responses adapter supports JSON/SSE text, refusals, native function calls,
verified call-result continuation and provider-reported usage. Requests use
`max_output_tokens` and `store=false`. Completed output items, including encrypted
reasoning, remain only in the active tool loop; saved conversation, audit and Undo
records exclude them. The existing four tools, permissions, readback and Undo
remain the execution authority.

Both adapters share bounded HTTP workers, deadlines, credential isolation and
cancellation. Truncated, failed or conflicting Responses output cannot execute
calls. Transport failure after a mutation preserves its receipt without replay.
Generation/credential changes also gate presentation updates under the service lock.

Credential-free fixtures cover protocol parsing, migration, HTTP streaming,
deduplication, cancelled queues and honest failure receipts. The native Minecraft
fixture selects/saves Responses and checks real FullBright Gamma changes and Undo.
This establishes fixture correctness; live model compatibility remains untested.

Minecraft 26.2 / Java 25, Styles and ordinary profiles remain compatible. See
provider details and limits. This completes the Responses
portion of Phase 1B; broader provider controls and later gameplay/context phases
remain pending.
