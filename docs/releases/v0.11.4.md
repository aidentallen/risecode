# 0.11.4 — Provider capability reports

AI Settings now offers a connection report that separates the client's declared
formats from behavior observed from the selected endpoint/model/protocol. Text,
native tools, streaming and token usage have independent results; untested formats,
the model's context window and pricing remain unknown.

Test formats attempts at most three bounded, harmless requests: JSON text, echo
tool when enabled and text SSE when enabled. One overall timeout bounds the
sequence; each output budget is capped at 1,024 tokens. It sends no game state or
history, offers no real client tools and never executes returned functions.
Positive format results do not grant permissions or establish planning quality.

Reports remain only in this session, with at most eight tested identities retained.
Different routes/models/protocols/output parameters cannot share proof, and changed
credentials clear all observations. Cancellation suppresses stale reports and
remaining requests. Counts are provider-reported and attributed to their actual
probe; missing usage is never replaced with estimates.

The Responses token-parameter button is visibly disabled with an explanation of
its fixed `max_output_tokens` behavior. The report remains scrollable with a fixed
Back control, and settings scroll bounds use actual content height.

Deterministic checks cover both protocols over real loopback HTTP, wrong/absent
formats, unsafe returned functions, malformed echo arguments, deadlines,
cancellation, report retention/identity and credential isolation. The native fixture
checks the report, disabled control and scrolling alongside actual module/Undo
behavior. Live model compatibility remains separately untested.

Minecraft 26.2 / Java 25, Styles, profiles and existing execution permissions remain
compatible. OpenRouter routing, additional model controls and OS secret storage
remain future Phase 1B work; this release adds no gameplay tasks or world adapters.
