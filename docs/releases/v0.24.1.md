# 0.24.1 — Joining-camera FOV fix

The camera can report zero before its first tick. RiseRecode previously passed that value
back through a positive-FOV setter even when Zoom was inactive, logging `Invalid FOV` while
joining. Inactive zoom now preserves the native value exactly. Active zoom skips unready
camera values and clamps positive results before conversion to float, avoiding underflow.
Hold/release magnification and the existing one-degree zoom minimum remain supported.

Minecraft 26.2 / Java 25 and all 0.24.0 performance controls remain unchanged.
This fixes the RiseRecode camera error; it does not repair Bobby's world-cache merge code.
See [the movement/crash investigation](../movement-crash.md) for the separate fatal exception,
workaround and limits of the available performance evidence.

Validation: `check build compileGametestJava` passed, including 35 runtime assertions
and the existing 304 performance assertions. The native camera/zoom fixture passed
16 assertions with Iris loaded and the installed mod set; clean process exit was
verified with Baritone omitted from the disposable test. With Baritone present the same
16 assertions passed, but its worker threads triggered the exit watchdog.
The later GUI investigation found that these camera fixtures did not activate Complementary
or copy the approved Bobby setting because their init script used a relative destination.
Those runs do not establish shader-pack coverage; see the investigation for the correction.

Installed checksum-verified into Fabric 26.2, with the prior JAR backed up and all 48 other
mod files and 24,877 config/map files preserved. Restart Minecraft to load this release.
