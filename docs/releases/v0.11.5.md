# 0.11.5 — Explicit OpenRouter routing

Historical release: the Agent feature and its guides were removed in [0.13.1](v0.13.1.md).

AI Settings now chooses Compatible or OpenRouter gateway mode explicitly.
Compatible and older saved profiles emit no OpenRouter-specific fields.
OpenRouter supports an optional ordered provider allowlist, supported-parameter
filter and requested deny-collection policy. Upstream provider fallback is fixed
Off; the client also performs no automatic retry or profile/protocol fallback.

The immutable preferences reach Chat Completions, Responses, all format probes
and every tool round. Routing is part of capability-report identity, so a changed
policy cannot reuse another route's observations. Reports distinguish requested
filters from unverified upstream behavior; local validation and permissions remain
the action authority.

Only official OpenRouter HTTPS API bases or loopback gateways accept this mode.
Provider slugs are bounded, keyboard-editable and validated before configuration
changes. Invalid or unknown stored policies preserve their original file. Routing
preferences are non-secret; session credentials stay outside profile JSON and
request bodies.

Deterministic checks cover both protocol payloads, migration, policy/endpoint
validation, immutable lists, route evidence isolation, real local HTTP probes and
failure without client fallback. Native Minecraft checks cover editing/hotkey
isolation, invalid-setting rejection, route-preserving probes and actual FullBright
changes/Undo. Hosted OpenRouter/model behavior remains separately untested.

Minecraft 26.2 / Java 25, Styles and existing client profiles are preserved.
Additional model controls, optional secret storage and later gameplay/context
milestones remain pending. See provider details.
